Build notes · 25–27 Sep 2026

How Dil Chahta Hai was built

A group trip decision tool for friends in India. The organiser shares one link and a PIN in WhatsApp. Everyone adds their budget, dates, trip type and deal-breakers. The app ranks 10 destinations from Pune so that nobody gets a trip they can't afford or hate, and the organiser marks the final choice.

How the work was done

From brief to live, step by step

Claude Code (Opus) did the building. The owner made every product decision; the gstack skills gave each phase a fixed routine: think, plan, build, review, test, ship.

  1. 25 Sep

    Office hours: challenge the brief

    /office-hours The scope was fixed by the brief. Only two questions were challenged: how to rank options fairly, and how to keep access simple without accounts. The result was a design doc that overrides the PRD where they differ.

  2. 25 Sep

    Engineering plan

    /plan-eng-review Locked the architecture: 14 files, all database access on the server, every action behind a guard, Supabase and Vercel both in Mumbai, Vitest for tests, and a daily keep-alive.

  3. 25 Sep

    Build the engine, in parallel

    Tasks T1–T5 and T7: scaffold, database schema, ranking engine, PIN and cookie access, server actions. Independent tasks ran as parallel agents, each in its own git worktree, then were merged.

  4. 26 Sep

    Review checkpoints 1 and 2

    /review Found and fixed security gaps: PIN tries now lock the database row per attempt, regenerating the PIN also replaces the organiser link, and cookies expire on the server after 60 days.

  5. 26 Sep

    Design system, three rounds

    ui-ux-pro-max Started clean, then warmer and more playful, then "vacation vibes": big photo headers of famous Indian and world places, photo cards for results, and a Domestic / International label.

  6. 26–27 Sep

    Pages, three agents at once

    A shared UI kit first, then the create page, the trip home + answers form, and the organiser page were built in parallel and merged.

  7. 27 Sep

    Real data

    Supabase project created in Mumbai, schema applied, and 10 destinations loaded with costs from Pune: Goa, Jaipur, Kerala, Manali, Rishikesh, Ladakh, Andaman, Bali, Santorini, Swiss Alps.

  8. 27 Sep

    Review 3 and QA, side by side

    /review/qa-only Four reviewers (security, correctness, design and accessibility, attacker's view) read the code while a fifth agent clicked through every page at phone size. About 20 fixes followed, each covered by tests.

  9. 27 Sep

    Ship

    Code merged to main, imported into Vercel, tested end to end on the live URL, a demo video recorded with Playwright, and all test trips deleted from the database.

The calls that shaped it

Key decisions

Ranking: floor, then average

Brief said: rank by the worst-off person first.

An option fails if anyone is blocked by a deal-breaker, is over budget, or scores under 40. Passing options rank by group average, then lowest score, then cost.

Access: PIN + pick your name

No accounts or passwords for friends.

A 6-digit PIN (10 tries, then a 15-minute pause), a signed cookie, and an "Is this really you?" check that blanks the budget if someone else's answers are reopened.

Server-only database

Option: let the browser talk to Supabase.

The browser never talks to the database. Every read and write goes through server code that checks the PIN cookie or the organiser link first.

Budgets stay private

Friends shouldn't see each other's numbers.

No friend's budget ever reaches the page. Results only say "comfortable", "tight" or "over budget".

Deadline in IST

Phones in different time zones.

The deadline is stored as 11:59:59 PM IST and checked on the server, not the phone.

Final choice locks answers

When does voting end?

At the deadline, when the organiser locks early, or when a final choice is marked. Everyone then sees "Decided: Goa, 10–14 Nov".

Checked by tests and review

Promises the code keeps

The browser never talks to the database.
No friend's budget amount ever appears on a page.
Every server action checks access first; a test fails if one doesn't.
Only the trip name is visible before the PIN is entered.
A lost connection shows a message, never a blank screen.
Every photo is credited to its photographer and licence.
